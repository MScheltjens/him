## Commands

pnpm 12 (pinned via `packageManager`), Node 24.

- `pnpm dev` — start dev server (Turbopack)
- `pnpm build` — production build
- `pnpm start` — run production build
- `pnpm lint` — ESLint (flat config, `eslint.config.mjs`)
- `pnpm typecheck` — route types (`next typegen`) + `tsc --noEmit`

There is no test suite configured in this repo. CI (`.github/workflows/ci.yml`) runs install → lint → typecheck → build on every PR and push to `main`; the build needs no secrets. Dependabot (`.github/dependabot.yml`) opens monthly PRs for npm (minor/patch grouped) and GitHub Actions updates. Deployed on Vercel.

Local env: copy `.env.example` to `.env.local` — `RESEND_API_KEY` (required to send the contact form), `RESEND_FROM_EMAIL` (optional, needs a verified Resend domain), `CONTACT_TO_EMAIL` (optional local-testing override for the recipient).

## Architecture

Single-page marketing site (German-language, industrial services business "HIM" in Hamburg) built on Next.js App Router.

- **`app/`** — routes only. `app/(site)/page.tsx` composes the homepage purely from section components in order (Hero → Intro → Services → Trust → Gallery → Faq → Cta → Contact → ImageBanner). `app/layout.tsx` wraps every route with `Header`/`Footer`, and also holds the site metadata (Open Graph/Twitter, using the hero Unsplash image), the `LocalBusiness` JSON-LD, and Vercel `<Analytics />`. Pages live in the `(site)` route group (URLs unchanged); legal pages (`impressum`, `datenschutz`) are separate routes.
- **Metadata routes** — `app/sitemap.ts` (hand-maintained URL list — add new pages there), `robots.ts`, `manifest.ts`, `not-found.tsx`, and generated favicons `icon.tsx`/`apple-icon.tsx`, which share `lib/og-icon.tsx` (a `next/og` `ImageResponse` with a hand-copied lucide "Ship" glyph, since Satori can't render lucide components).
- **`components/sections/`** — one component per homepage section, matched 1:1 to a data object in `data/site.ts`. To change homepage copy, edit `data/site.ts`, not the section components (components are presentational and read from these exported objects).
- **`components/layout/`** — header, footer, and `image-banner`/`logo-mark`.
- **`components/ui/`** — shadcn/ui primitives (installed via `components.json`, style `radix-nova`, Radix + `lucide-react` icons). Regenerate/add primitives through the shadcn CLI conventions implied by `components.json` rather than hand-rolling equivalents. Notable custom primitive: `theme-image.tsx`, a wrapper around `next/image` for the Unsplash-backed imagery pattern below.
- **`data/site.ts`** — all copy/content for the homepage sections as typed exported consts (`hero`, `intro`, `services`, `trustSection`, `gallerySection`, `faqs`, `contactSection`, etc.), including nav items and footer links, plus business details (`site`: name, phone, email, city) and `siteUrl`/`siteTitle`/`siteDescription` used by metadata and the sitemap.
- **`data/images.ts`** — image content is Unsplash-hosted, not local: each `SiteImage` is `{ id, alt, credit }`, and `unsplashUrl(id, width)` builds the URL. `next.config.ts` whitelists `images.unsplash.com` via `images.remotePatterns` — any new external image host must be added there.
- **`lib/actions.ts`** — `sendContactMessage`, the Server Action behind the contact form (`components/sections/contact.tsx`, wired with `useActionState`). Validates input server-side (German error messages, length limits, honeypot field `company`), sends the notification via Resend with `replyTo` set to the sender, then a best-effort auto-reply whose failure doesn't fail the submission. Missing `RESEND_API_KEY` returns a friendly error instead of throwing.
- **`lib/utils.ts`** — `cn()` (clsx + tailwind-merge), the standard shadcn helper.
- **`next.config.ts`** — security headers for every route (nosniff, referrer policy, frame denial, Permissions-Policy); HSTS is left to Vercel. Keep these in place when editing the config.

### Styling

Tailwind v4, CSS-first config in `styles/globals.css` (no `tailwind.config.*`). Key points when touching styles:

- Theme tokens (`--background`, `--primary`, `--secondary`, `--accent`, etc.) are defined as a "warm concrete + harbor teal + safety orange" palette in `:root`/`.dark`, then re-exposed via `@theme inline` for Tailwind utility generation. Prefer the semantic tokens (`bg-primary`, `text-muted-foreground`, ...) over raw palette colors.
- `--radius` is set to `2px` sitewide (deliberately sharp/industrial corners) — don't reintroduce rounded defaults.
- Reusable utility classes are defined in `@layer utilities` in `globals.css`: `.container-page`, `.section-padding`, `.surface-soft`/`.surface-elevated`, `.section-divider`, `.brand-gradient`, `.accent-gradient`, `.hero-grid`. Use these instead of re-implementing the same patterns inline.
- Legacy `blue-*` Tailwind utilities are remapped to the harbor teal palette for compatibility — new code should use `harbor-*`/semantic tokens directly rather than `blue-*`.

### Imports

ESLint enforces `simple-import-sort` (imports and exports) — import order is auto-fixable via `pnpm lint --fix`, don't hand-sort.
